# User journey

## Primary journey: tenant or advocate intake

1. **Start a case** — user chooses metro/jurisdiction and enters a location at the level needed for a public-record search. Avoid collecting unnecessary personal identifiers.
2. **Describe the situation** — free text plus optional structured fields: issue type, dates, notice received, hearing date, immediate safety concern, and preferred contact/referral needs.
3. **Review extracted facts** — the system presents a summary and asks the user to correct errors before searching.
4. **Evidence search** — retrieve relevant public 311/building records and contextual data. Display match rationale, dates, status, distance/geography, and limitations.
5. **Rights and resources** — surface jurisdiction-specific statutes, procedural information, and assistance programs. Mark each as potentially relevant and show eligibility conditions requiring confirmation.
6. **Evidence gaps** — explain what was not found and suggest safe documentation or official inspection/assistance channels.
7. **Generate brief** — create a structured draft with citations, confidence/uncertainty labels, and reviewer checklist.
8. **Human review** — advocate or attorney verifies facts, law, deadlines, and referrals before action.

## Critical interaction principles

- Do not ask for sensitive personal details unless essential.
- Explain why location is requested and how it is used.
- Provide an obvious edit path when extracted facts are wrong.
- Use plain language; define legal terms.
- Distinguish an emergency safety concern from routine housing maintenance.
- Do not imply that a public 311 record refers to the tenant's exact unit unless the source explicitly establishes that.
- Show source dates; stale data must be labeled.
